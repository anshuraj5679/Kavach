# Kavach: an AI data-leak guardian for campus portals

*Kavach* (कवच) means **shield**. It is an armour layer that sits in front of a college portal as middleware, inspects **every request in and every record out**, stops data leaks, and explains what happened in plain language.

Built for a web-security hackathon (Track 2 · Mission Portal Shield). It has three parts plus an attack simulator:

| Part | Where | What it is |
|---|---|---|
| Fake campus portal | `http://127.0.0.1:8000` | "Northfield Institute of Technology & Management": a **fictional** college with 1,000 Faker-generated students and five deliberate, labelled weak spots |
| Kavach agent | `agent/` | FastAPI/Starlette middleware: inspector → scanner → detector → actions → ledger → explainer |
| Security dashboard | `http://127.0.0.1:8000/admin` | Live threat feed, incidents, leak ledger, AI reports, and the big **Agent ON / OFF** switch |
| Attack simulator | `attacks/simulate.py` | Runs seven attacks, **localhost only** |

> **Fake data only. Fictional college. Localhost only.** Every name, USN, phone, Aadhaar-style number, address, mark and fee record is generated by Faker from a fixed seed. The portal is deliberately vulnerable for teaching. It binds to `127.0.0.1`, and the simulator refuses any other target.

## Setup

Requires Python 3.11+.

```bash
pip install -r requirements.txt
python run.py
```

* Portal: <http://127.0.0.1:8000>
* Dashboard: <http://127.0.0.1:8000/admin> (served to localhost only)

Helpers:

```bash
python run.py --accounts   # print demo logins
python run.py --reseed     # rebuild the fake database (same seed → same people)
python run.py --reset      # clear the Kavach ledger before starting
```

### Optional: AI-written reports

Reports work **offline** with a built-in template. To have an LLM write them, set one key before `python run.py`:

```bash
export ANTHROPIC_API_KEY=...          # Claude (default model: claude-opus-5-5)
# or
export OPENAI_API_KEY=...             # requires: pip install openai
export LLM_MODEL=...                  # optional model override
```

On Windows PowerShell use `$env:ANTHROPIC_API_KEY = "..."`. The dashboard header shows which writer is active, and every report says `written by: llm` or `written by: template`.

## The 3-minute demo script

**Setup (before you present):** `python run.py` in one terminal, the dashboard open on the projector, a second terminal ready.

**0:00 · The portal.** Open <http://127.0.0.1:8000>. "This is a typical college portal: results, library, fees, admissions." Point at the ribbon: fictional college, fake data. Log in as 101 (`05032004`, `NITM240101`) and show the results page. Point at the URL: `/results`.

**0:30 · Agent OFF.** On the dashboard, flip the switch to **OFF**. The header turns red and the banner reads *"Agent is OFF: requests go straight to the database."* Run:

```bash
python attacks/simulate.py all
```

Read the red lines out loud: **300** students' results scraped, **420** library borrowers' phone, Aadhaar and address exposed, **1,000** applicants dumped by SQL injection, **20** other students' fee receipts read (including plain-text passwords), the real Priya **locked out of her own account**, Kavya's password cracked, and a hijacked session. Then turn to the dashboard: **it shows nothing.** "That is today's reality: the college never finds out."

**1:15 · Agent ON.** Flip the switch to **ON** (the colour turns green). Run the same command:

```bash
python attacks/simulate.py all
```

Watch the dashboard fill in live:

* **Scraping**: 3 records got out, then Rahul's device was blocked and his account frozen (OTP re-verification).
* **Over-exposure**: phone, Aadhaar and address **masked in flight**; the 420-row dump **stopped**.
* **SQL injection**: blocked **before the database was touched**.
* **Receipt IDOR**: refused on the first try.
* **Lockout attack**: the attacker is blocked after 5 tries, before the portal's own 10-try lock. **The real Priya still logs in.** A classmate on the same Wi-Fi IP, on her own device, logs in fine too.
* **Password guessing**: blocked after 5 guesses.
* **Session hijack**: a cookie replayed from another device is rejected.

**2:15 · Explain.** Click the critical *Results scraping* incident. The AI report covers what happened, why it was flagged, the exact impact, the action taken, and **the root-cause code fix** pointing at `WEAK SPOT #1` in `app/portal.py`. Switch to the *Student notice* tab: a draft email for the 3 affected students. Scroll to the **leak ledger**: whose record, which fields, to whom, from which IP, and when.

**2:45 · Close.** "Rules decide, the AI explains. Kavach doesn't replace fixing the portal: it buys the college time, tells them exactly what to fix, and tells students the truth."

Shortcut for rehearsal: `python attacks/simulate.py all --compare` runs everything with the agent OFF and then ON, and prints a side-by-side table.

## How Kavach works

```
request → inspector → (portal + DB) → scanner → detector → actions → ledger → dashboard
                                                                       ↘ explainer (LLM or template)
```

| Stage | File | Does |
|---|---|---|
| Gateway | `agent/gateway.py` | Starlette middleware that every request and response passes through; issues the device-ID cookie |
| Inspector | `agent/inspector.py` | SQL-injection patterns (before the DB), ownership mismatch (`?roll=` / `?userId=` ≠ session), session guard, `client_ip()` |
| Scanner | `agent/scanner.py` | Splits outgoing records into the viewer's own and other people's; finds PII **by field name and by value pattern** (10-digit phone, `xxxx xxxx xxxx` Aadhaar, email); masks other people's PII; strips passwords; counts rows for mass-dump detection |
| Detector | `agent/detector.py` | Sliding-window counters per IP + device + roll; risk score 0–100 with reasons and severity; optional IsolationForest anomaly score |
| Actions | `agent/actions.py` | Block IP + device, freeze account (OTP stub), end session, stop response, branded 403 page |
| Ledger | `agent/ledger.py` | Incidents, one row per leaked or masked record, live events, stats, blocks. SQLite-backed (`data/ledger.db`, survives restarts) with an in-memory cache |
| Explainer | `agent/explainer.py` | Admin report, student notice and severity, cached per incident version |
| Notifications | `agent/notify.py` | In-app alerts to the student (portal bell and Account page) and to the IT head (dashboard) |
| Config | `agent/config.py` | **Every threshold** and the palette tokens |

### Rules decide, the AI explains

Every allow, mask or block decision comes from the deterministic thresholds in `agent/config.py`:

| Setting | Default | Meaning |
|---|---|---|
| `FOREIGN_RECORD_LIMIT` | 3 | other people's records an actor may see in the window before being blocked |
| `ROW_SPIKE_LIMIT` | 100 | other people's rows in one response that count as a mass dump (response stopped) |
| `FAILED_LOGIN_LIMIT` | 5 | wrong tries per IP + device (the portal's own lock is at 10) |
| `SHARED_IP_LOGIN_LIMIT` | 3 | tries for other devices on an IP that already has a blocked device |
| `IP_FAILED_LOGIN_CEILING` | 20 | all devices on one IP combined (catches attackers who drop cookies) |
| `WINDOW_SECONDS` | 300 | sliding window |

The anomaly model can raise an incident's risk score but never overrides a hard rule. The LLM receives only **structured facts** (counts, field *names*, record ids, timestamps, the root-cause mapping), never raw personal data, and it never sees a live request.

### The three personal-account protections

1. **Lockout shield: block the attacker, not the student.** Every browser gets a secret device-ID cookie. Failures are counted per **IP + device**, not per USN, and the attacker's device is blocked at 5 tries, before the portal's 10-try USN lock can trigger. On shared campus Wi-Fi: same device as the attacker → blocked; same IP, different device → allowed with fewer tries; different IP and device → normal. The student and the IT head are notified: *"Someone tried your account 5× from IP x. Kavach blocked that device. Your account is NOT locked."*
2. **Session-hijack guard.** Each session is bound to the device it was created on. The same cookie arriving from another device ends the session. A 10-minute idle timeout covers an abandoned lab PC (same device, same IP), and *Log out from all devices* is on the Account page.
3. **Forgotten login on someone else's phone.** A device the student has never confirmed is **untrusted**: the student is notified on first login, and the session ends after 3 idle minutes, after 15 minutes in total, or when the network (IP) changes. Each new-device alert has *"This wasn't me: log out everywhere"* and *"Trust this device"* actions.

> A website cannot read a MAC address. Kavach uses the device-ID cookie plus the IP.

> `client_ip()` reads `X-Forwarded-For` so the simulator can play several attackers from one machine. In production, trust that header **only** from your own reverse proxy.

## The deliberate weak spots

Each is marked `# WEAK SPOT` in the code, with a `# SAFE VERSION:` comment showing the fix.

| # | Where | Flaw | What Kavach does |
|---|---|---|---|
| 1 | `app/portal.py` → `api_results` | IDOR: `?roll=` is never checked against the session | counts foreign records, blocks + freezes after 3 |
| 2 | `app/portal.py` → `api_library_borrowers` | `SELECT *` sends phone/Aadhaar/address the page never shows; no `?limit=` cap | masks PII in flight; stops dumps over 100 rows |
| 3 | `app/portal.py` → `api_admissions_search` | SQL built by string concatenation; raw DB errors echoed | blocks the pattern before the DB |
| 4 | `app/portal.py` → `api_fee_receipt` | IDOR on `?userId=`, plus `SELECT *` leaks Aadhaar and password | refuses foreign receipts, blocks after 2 |
| 5 | `app/auth.py`, `app/portal.py` | DOB passwords, ID-card number as "second factor", per-USN lockout, sessions never expire and aren't bound to a device | lockout shield, session guard, untrusted devices |

## Attack simulator

```bash
python attacks/simulate.py all                 # everything, against the current agent state
python attacks/simulate.py all --compare       # OFF then ON, side by side (leaves the agent ON)
python attacks/simulate.py scrape              # or: overexposure | sqli | receipt | lockout | bruteforce | hijack
python attacks/simulate.py sqli --target http://example.com   # → REFUSED
```

Each attack comes from its own fake attacker IP (`X-Forwarded-For`), so blocking one does not hide the next. `all` resets the ledger, blocks and portal lockouts first (`--no-reset` to skip). The host guard accepts only `127.0.0.1`, `localhost` or `::1`, and also checks that the name resolves to a loopback address.

## Project structure

```
app/
  main.py        FastAPI app: portal + dashboard routes + agent middleware
  db.py          SQLite schema + Faker seeding (fixed seed)
  portal.py      portal pages + APIs (with labelled weak spots)
  auth.py        two-step login, sessions, device IDs, portal lockout
agent/
  gateway.py  inspector.py  scanner.py  detector.py  actions.py
  ledger.py   explainer.py  notify.py   config.py
static/
  portal.css  dashboard.css  layout.html  pages/*.html  *.js  blocked.html
attacks/
  simulate.py
run.py  requirements.txt  README.md
data/            (created at runtime: portal.db, ledger.db)
```

## UI notes

* Two coordinated themes driven by CSS variables: light, institutional portal (`static/portal.css`) and dark SOC dashboard (`static/dashboard.css`).
* Motion with meaning: feed items slide in, stat tiles count up and pulse when they change, and the whole dashboard flips from green to red when the agent is switched off. All of it respects `prefers-reduced-motion`.
* Clear states: loading skeletons, empty states, a branded *Blocked by Kavach* page (never a stack trace), inline blocked cards in the portal, and a reconnecting indicator on the dashboard.
* Accessibility: labelled controls, visible focus rings, `role="switch"` toggle, `aria-live` threat feed, a modal report drawer with focus return and Esc to close, keyboard-navigable tabs, and severity always shown as text, never colour alone.
* Deep link to a report: `/admin#INC-0001`.
